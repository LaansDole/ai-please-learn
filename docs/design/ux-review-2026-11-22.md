# EvoLab UX review — live site (ai-please-learn) + demo page

Reviewed live at `https://laansdole.github.io/ai-please-learn/` (app) and `https://laansdole.github.io/ai-please-learn/demo/` (demo), desktop only, dark theme, 1440×900 and 1024×768. Source cross-checked in `/Users/laansdole/Projects/evolab` at HEAD `fb0d492`. Method: single-context review (source read + live Chromium driving + `impeccable detect --json`), not the full dual-sub-agent `/impeccable critique` workflow — no `PRODUCT.md`/`DESIGN.md` exist in the repo, so no brief to check against beyond the incumbent implementation.

Journeys walked: (a) first load → every built-in game → steps 1–4 → NEAT run to gen 1572 → Hall of Fame replay → back to live; (b) Create → Settings providers → no-API-key state → back; (c) Gallery ↔ demo page round trip; (d) keyboard-only tab order on gallery header/cards.

No P0s: nothing observed blocks task completion or loses data across the journeys walked.

**Over-built / cut candidates:** none found. The raw-JSON editor alongside the weight sliders on the Rewards step looks redundant at a glance but both write the same `RewardConfig` and the code comments tie it to an explicit spec section (11.4) rather than speculative scope — leaving it as-is.

**Good now (confirmed live):**
- Hall of Fame replay round-trips cleanly: pick a past generation's champion, watch it, "Back to live" resumes the running session without losing history.
- Create page's no-API-key state gives two concrete unblockers instead of a dead end.
- Keyboard tab order on the gallery (brand → Gallery/Create/Settings/GitHub → demo link → first card) is logical and every stop shows a visible focus ring (global `:focus-visible` rule in `app.css`).
- The 4-step concept stepper shows done/active state clearly and stays reachable at every width tested.
- Gallery page scans clean under `impeccable detect` (0 findings) at 1440×900.
- Disabled-state contrast (`--faint` ≈2.5:1) is low in absolute terms but WCAG exempts disabled controls from the 4.5:1 text requirement, so this is not flagged as a violation.

## `impeccable detect --json` — raw summary

- `src/ui` (directory scan): `[]` — detector scans markup/URL targets, not plain `.ts` DOM-builder modules, so this returned empty; the meaningful scans were the live-URL passes below.
- Live `https://laansdole.github.io/ai-please-learn/` (gallery, 1440×900): `[]` — clean.
- Live `https://laansdole.github.io/ai-please-learn/demo/` (1440×900): 3 findings —
  1. `line-length` (warning) — `div.sub`, ~203 chars on 2 rendered lines (aim <80).
  2. `line-length` (warning) — `div.panel:nth-of-type(1) > p.note`, ~130 chars on 3 rendered lines.
  3. `straggler` (advisory) — `div.panel:nth-of-type(2) > p`, lone word "runbook." on its own last line (12% of measure).
- Live deep links (`/snake/4`, `/create`, `/settings`, 1440×900): detector reported `HTTP 404` and skipped scanning. This is a detector limitation, not an app bug: GitHub Pages has no rewrite rules, so Vite's build intentionally ships `404.html` as a copy of `index.html` (`vite.config.ts`, `spaFallback` plugin) — a real browser renders the full app at that status code (confirmed live via direct `tab.goto()` to all three routes, screenshots render correctly), but the detector's fetch-based scan bails on the non-200 status before executing/rendering the page.
